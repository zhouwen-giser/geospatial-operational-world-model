## Selective concept reference

The implementation may study, then independently reimplement, only these concepts:

- required/transit selection, fractional service ledgers, boundary candidates, and portal policies;
- canonical problem construction, fixed-point objectives, route signatures, diversity, ranking, and bounded Pareto selection;
- closed/open directed postman, required-component connection, small exact oracles, candidate pools, and resource admission;
- independent continuity, obligation/terminal, turn, and metric verification;
- alternative-pipeline and generation-fenced asynchronous lifecycle concepts.

Every implementation is written against the v0.6 contracts and repository architecture with fresh naming, tests, error behavior, and persistence. Reference file hashes are recorded in `reports/gowm-v0.6/source-lock.json` solely to make the reviewed input set auditable.

## Mandatory predecessor reuse

`V0_5_NETWORK_AUTHORITY` and `NO_SECOND_GRAPH` are hard gates. v0.6 must reuse the authoritative v0.5 GraphVersion, Node, Edge, Directed Arc, turn rules, profiles, condition snapshots, snap, shortest path, cost matrix, and RoutingSnapshot semantics through `gowm_network_v1` or pure network-query-core APIs.

- optimizer sidecar, OR-Tools, fleet, clustering, depot assignment, multi-route repair, capacity, and time windows;
- the legacy planner database, migrations, graph ownership, API contracts, OIDC/tenant/auth code, and dispatchable-result claims;
- all `node_modules`, `dist`, coverage output, `.env`, generated artifacts, and historical gate conclusions;
- reference test PASS claims as evidence for this repository.

Tests and fixtures may inform scenario ideas, but v0.6 evidence must be generated by this repository against its own contracts and real runtime.
